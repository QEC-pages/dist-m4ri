Overview

dist-m4ri computes, or brackets, the minimum distance of a binary classical linear code, of a quantum CSS code, or of a detector error model (DEM) generated by Stim. It implements two algorithms and their combination:

  • Random information sets (also, random window or RW, method=1): finds low-weight codewords, i.e., an upper bound dmax on the distance.
  • Connected clusters (CC, method=2): exhaustive search over clusters of increasing weight, which gives a certified lower bound dmin, or the exact distance once a codeword is found.
  • Bracketing (method=3, the default): RW and CC run concurrently on a common pool of threads until the two bounds coincide, dmin = dmax, or another stop condition is met (e.g., the timeout, 60 s by default).

The package contains the multithreaded program dist_m4ri, the legacy single-threaded program dist_m4ri_old, and the Python wrapper dist_m4ri.py (NumPy and SciPy matrices, Stim circuits and DEMs, a persistent cache of the results). This page summarizes how the program works; README.md describes all parameters (also dist_m4ri --help and dist_m4ri --morehelp; dist_m4ri --help maxC shows the help of one parameter).

Codes and matrices

  • Classical code: only the parity-check matrix H is needed (finH=...); the codewords are the non-zero binary vectors c with H c = 0.
  • Quantum CSS code: H = Hx and either G = Hz (finG=...) or the logical operators L = Lx (finL=...); the codewords are the vectors c with H c = 0 and L c != 0 (Z-type logical operators). With G, the matrix L is constructed automatically. For the other sector, swap the roles of Hx and Hz; the CSS distance is the smaller of the two (the Python function compute_css_distance() runs both sectors).
  • DEM: fdem=... gives H (detectors) and L (observables), with one column for each error mechanism; the distance is the minimum number of error mechanisms which trigger no detector but flip an observable. Equal columns (error mechanisms with the same detectors and observables) are merged by default (merge=1): a codeword with two equal columns is not of minimum weight, since dropping both gives a lighter one. Detectors are dropped if this is verified to be exact (every column touching them has a twin which does not): by default (drop=auto), the binary searches for the largest such set from the DEM alone, e.g., the minority-basis detectors of a CSS circuit, so that the full DEM is reduced to the size of the simplified one; drop=FILE gives the detectors in a file, and drop=0 keeps all (the Python options --simple and --full are disabled since version 0.13.0).

All matrices are binary, with n columns, in Matrix Market format (.mtx or .mmx). For a CSS code, they obey the orthogonality conditions Hx Hz^T = 0, Hx Lz^T = 0, and Lx Hz^T = 0, and the number of encoded qubits is k = n - rank(Hx) - rank(Hz), which is also the rank of Lx Lz^T for complete sets of logical operators Lx and Lz. With debug=16, the program prints the ranks of the input matrices and k.

How it works: RW algorithm (method=1)

Each RW step computes the reduced row echelon form of H with the columns taken in a random order. This fixes an information set, the n - rank(H) non-pivot columns. Each non-pivot column j gives a vector in the null space of H, with a 1 at position j and its other non-zero entries at pivot positions; such vectors have at most rank(H) + 1 non-zero entries and tend to have small weights, which qualitatively explains why the algorithm works. A codeword c is found in a step if exactly one of its positions is a non-pivot column, and every codeword of the minimum weight is found with some column order (see the QDistRnd manual, Sec. 3.1). The candidates with L c != 0 are kept in a hash table, together with the number of times each of them has been found (hit counts). For matrices with at least 128 rows, the elimination processes 20 or 24 pivots per pass over the rows ("Method of the Four Russians", with tables of combinations of the pivot rows), which gives the same result about twice as fast for large matrices.

Variants: kwin > 0 localizes the column order around a random column (for n >= 500, every other step by default). With ksub > 0 (experimental, should not be used; a warning is printed), each step reduces the span of ksub rows of a fixed basis of ker(H) (cache-resident elimination): a few codewords are then found much more often than others, so that the hit-count criterion min_hits may end RW early.

RW ends after steps steps (default: 100000), at the timeout, as soon as a codeword of weight at most wmin is found, or when the hit-count criterion min_hits is met (see Convergence below).

How it works: CC algorithm (method=2)

The connected-cluster algorithm grows clusters of columns. A cluster starts at a column i and only uses columns j > i; at each level, a column is added from the support of the first check that is not satisfied by the cluster. Round w enumerates all such clusters of weight w (the start columns are distributed among the threads; with few start columns per thread, a start column is split into work units which also fix the first one to three columns added). A round without codewords raises the lower bound to dmin = w + 1, and a codeword found in a round gives the exact distance. This search finds every minimum-weight codeword, starting from its smallest column: a proper subset of a minimum-weight codeword has a non-zero syndrome (otherwise, the subset or the rest of the codeword would be a lighter codeword), and the support of its first unsatisfied check contains another position of the codeword [DKP17]. The work of round w grows roughly as n (D - 1)^(w - 1), where D is the maximum row weight of H. With smax=0 (default), the syndrome of a cluster is kept as a bitset, and the last column of a cluster is found by a hash lookup: the syndrome left after the next-to-last column must be that of a single column of H. The first unsatisfied check is taken in the order of the rows of H: for matrices, the rows are sorted by increasing weight (sort_rows=1, the default), which reduces the work when the row weights are very different; the detectors of a DEM are kept in time order (sort_rows=0, the default with fdem), which is better there.

The expert options start, cbeg/cend, and noscan restrict the search; each of them prints a warning, since the reported dmin is then not necessarily a lower bound (dmax is always valid). With smax > 0, CC also computes the confinement profile, the minimum non-zero syndrome weight for each cluster weight.

How it works: bracketing (method=3)

The coordinator splits the threads between CC and RW for each CC round, according to the predicted CC work of the round (the measured work of the previous round times its growth factor), the measured time of a RW step, the number of remaining RW steps, and the remaining time. Once a codeword of weight dmax is known, the round w = dmax - 1, which certifies dmin = dmax, runs on all threads; the expected distance dexp only affects the thread split before RW finds any codeword. When RW converges (min_hits) or runs out of steps, its threads join the CC rounds. A CC round predicted not to finish before the timeout is not started while RW runs. With a stop target dstop = U (not an upper bound), the run ends as soon as CC has certified dmin >= U, unless a codeword of weight < U is found; e.g., for a CSS code with d = min(dX, dZ) <= U already known, the sector runs need no more.

Convergence of RW

The RW upper bound is not certified unless CC confirms it. As in QDistRnd (manual, Sec. 3.3), the probability to miss a codeword lighter than the minimum weight w found is estimated from the hit counts: if the m codewords of weight w were found n_1, ..., n_m times, then P_fail < exp(-<n>), where <n> = (n_1 + ... + n_m) / m is the average number of times a minimum-weight codeword has been found. This assumes that all codewords of the same weight are found equally often, which is tested with a dispersion test of the hit counts (a warning is printed with debug=1 if the hit counts are strongly non-uniform). The second estimate assumes uniformly random information sets: a given codeword of weight w is found in one step with the probability P1(w) = w C(n-w, s-1) / C(n, s), where s = n - rank(H) is the number of non-pivot columns and C(a, b) is the binomial coefficient. See the section "RW Convergence: Empirical Test and Probability to Find a Codeword" in README.md for details.

Output

The program prints one line to stdout, dmin dmax rw_steps: dmin - 1 is the largest cluster weight analyzed by CC without finding a codeword, dmax the smallest weight of a codeword found (or the supplied upper bound dmax; never the stop target dstop), and rw_steps the number of completed RW steps (0 if CC found a minimum-weight codeword); dmin = dmax is the exact distance. All diagnostic output goes to stderr, as selected by the debug bitmap (default: 3, the summary and the progress; debug=0 is silent, debug=7 adds a periodic status line). Compilation and tests

The program is intended for use with recent gcc compilers under Linux, and it uses the m4ri library for binary linear algebra. To install the library under Ubuntu, run

sudo apt-get update -y
sudo apt-get install -y libm4ri-dev

Then run make -j all in the src directory, which compiles dist_m4ri and dist_m4ri_old; make test runs the C test suite, and pytest tests/test_dist_m4ri.py (from the repository root) the tests of the Python wrapper.
