Todo Notes for dist_m4ri Program

1. High-Priority Roadmap: High-Performance RW Overhaul

This work optimizes the Random Information-Set Decoding (RW, method=1) algorithm to achieve linear multicore scaling (32–128 cores), minimal per-core memory footprint, and enhanced hit rates for quantum CSS codes and Detector Error Models (DEMs).

Inspired by sqetch (arXiv:2607.28795, Appendix H) and the empirical convergence criteria in QDistRnd (http://github.com/QEC-pages/QDistRnd).

Implementation Strategy

  • Stage 1 (Immediate / Functional Baseline):
    • Implement Tasks 1–4 using libm4ri matrix primitives (mzd_kernel_left_pluq, mzd_copy_row, mzd_echelonize).
    • Validate mathematical correctness, hit-rate scaling, and backward compatibility (ksub=0 retains original RW).
  • Stage 2 (Hardware-Optimized SIMD Engine):
    • For worker thread hot loops ($k_{\text{sub}} \le 64$), replace libm4ri with a zero-allocation, thread-safe, header-only AVX2 / AVX-512 bit-matrix kernel.
    • Utilize bit-sliced column representations (uint64_t cols[n]) to eliminate column transposition passes and completely remove the global m4ri_mem_mutex.

Task 1: Subspace Sketching (ksub, experimental) for In-Cache Multicore Scaling

  • Add CLI parameter ksub=[int] (default 0 retains original full-matrix RW).
  • Main Thread Precomputation:
    • Compute a basis of the null space $N = \ker(H)$ (dimension $\nu \times n$, where $\nu = n - \mathrm{rank}(H)$) once using mzd_kernel_left_pluq.
    • Store $N$ as a global read-only matrix shared across worker threads.
  • Worker Thread In-Cache Working Set:
    • For $k_{\text{sub}} > 0$, allocate a compact $k_{\text{sub}} \times n$ matrix instead of the full $m \times n$ check matrix.
    • For $k_{\text{sub}} = 64$ and $n = 5000$, working memory per thread is $\approx 40\text{–}80 \text{ KB}$, fitting entirely within private L1/L2 cache and eliminating L3 cache and DRAM bandwidth contention.
  • Per-Trial Hot Loop:
    1. Sample $k_{\text{sub}}$ distinct rows of $N$ (partial Fisher–Yates shuffle of the row indices; rows drawn with replacement would repeat and reduce the rank) into the thread-local working matrix M_sub.
    2. Perform in-place RREF via gauss_one(M_sub, perm->values[i], rank) in permuted column order (stopping as soon as rank == ksub, avoiding matrix transpositions and non-thread-safe m4ri_mmc allocations).
    3. Directly extract candidate codewords from the reduced non-zero rows (already in sorted original column coordinates; no dual transposition, coordinate unpermutation, or qsort needed).
    4. Test logical non-triviality against $L$ (column masks of $L$, see Faster Logical Check), and atomically update dmax.
  • Findings (Oct 2026, ksub forced also for $m < \nu$, 8 threads): ksub explores only the span of $k_{\text{sub}}$ rows of the fixed basis $N$ in each step, so a codeword is found only if all basis rows in its expansion are sampled. The hit counts are then concentrated on a few codewords, and min_hits stops RW early: e.g., for bb72_si1000_X.dem, after $\sim 2500$ steps with only 4–7 distinct codewords of weight 6 (full RW: 100 distinct codewords after $\sim 40000$ steps); for torus60_d14_X.dem, a codeword of weight 6 took 3–14 s instead of 3–15 ms. For c1920H.mmx (where ksub is allowed), the lightest codewords found in 20 s were similar to full RW. The fallback rule $m < \nu \Rightarrow$ ksub=0 thus stays (it disables ksub for DEMs and most quantum codes).
  • ksub is kept for now, but marked experimental (should not be used) in the documentation, --help, and --morehelp; a warning is printed whenever ksub>0 is given for RW (with or without min_hits, regardless of debug; in Python, once per compute_*_distance() call, and again in the binary's stderr, which Python prints if verbose or a debug bit of the binary is set), as a reminder that the option does not do what it is supposed to. The fallback to ksub=0 for $m < \nu$ is reported only with debug&1 (the binary's default, not Python's).
  • Find a subspace sampling for which the hit counts are uniform (or drop ksub). See also ../qec-cert/doc/algorithms-ub.tex, Sec. "Why Row-Sum Premultiplication (`ksub`) Fails at Large Weight" (Theorem thm:ub-ksub): a sum of $k_{\text{sub}}$ systematic rows needs $d - k_{\text{sub}}$ columns of the codeword among the pivots, and pre-mixed rows bias the hits toward codewords aligned with the basis; qec_cert's Stern ISD has no such option. This supports dropping ksub (with the refresh of Task 3 and the RCU item).

Task 2: Localized & Windowed Column Permutations for DEMs

  • Add parameters kwin=[int] (window size $W$ in every step; default 0: uniform random permutations, and for $n \ge 500$ an index window of win_hyb columns on every other step, since 0.17.0 for matrices only with rw_opt=0 or win_hyb > 0, see RW windows for big DEMs in section 2; alias win=[int]) and win_mode=[0|1] (default 0). A negative kwin (e.g., -1) turns the windows off (uniform random permutations in every step; documented, and passed by the Python wrapper, since 2026-11-07).
  • Window Construction:
    • Pick a seed column $j_0 \in [0, n-1]$ uniformly at random per trial.
    • Mode 0 (Tanner Graph BFS Neighbors): Perform BFS on the bipartite graph between columns and check rows starting from $j_0$ to gather $W$ geometrically/physically connected error mechanisms. Use a monotonic visit marker to avoid clearing arrays across trials.
    • Mode 1 (Spacetime / Index Proximity): Define a contiguous coordinate window $[j_0, j_0 + W) \pmod n$ around $j_0$.
  • Permutation Layout:
    • Place the internally shuffled $W$ window columns in the first $W$ positions ($0 \dots W-1$).
    • Place the remaining $n - W$ columns at the tail ($W \dots n-1$).
  • Support Overlap Filter & Windowed Echelonization:
    • Optionally restrict row sampling to basis vectors of $N$ whose support intersects window $W$. Done as a preference, with the experimental ksub only: in a window step, up to 4 redraws per sampled row for a row of $N$ meeting the window (always on, no option).
    • Exploit left-to-right echelonization: Gaussian elimination pivots first on the window columns, producing localized candidate codewords with support concentrated around the seed column $j_0$.

Task 3: Adaptive Basis Evolution & Periodic Refresh of $N$

  • Density Degradation Prevention:
    • Avoid unconstrained random row mixing ($N_i \leftarrow N_i \oplus N_j$), which quickly drives basis row weights to $\approx n/2$ and degrades ISD hit rates.
  • Steinitz Exchange with Discovered Codewords:
    • Maintain an atomic pool of the lowest-weight non-trivial logical codewords found by worker threads.
    • Periodically substitute these lighter codewords into the basis $N$ using Gaussian elimination to maintain linear independence while systematically reducing the average row weight of the basis.
    • Done differently (experimental ksub only, at each refresh below): one codeword of the minimum weight from the codeword hash (no separate pool) replaces the heaviest row of the re-echelonized basis $N$ whose pivot column is in its support, if that row is heavier, so that $N$ stays a basis of $\ker H$; the next refresh re-echelonizes $N$ again, so that the row weights are not reduced systematically.
  • Periodic Re-Echelonization (refresh=[int]):
    • Every refresh trials, generate a fresh canonical basis of $\ker(H)$ by re-echelonizing under a new global column permutation $\Pi$ (protected by a per-batch pthread_rwlock_t). This breaks sampling blind spots without accumulating row density.
  • Lock-Free Double Buffering (RCU Pattern) (only for the refresh of the experimental ksub; moot if ksub is dropped, see Task 1):
    • Maintain _Atomic(mzd_t *) N_active and background buffer N_staging.
    • Worker threads acquire a local snapshot of N_active per batch without locking.
    • The coordinator prepares N_staging and atomically swaps N_active with release semantics.

Task 4: Hit-Count Stopping Criterion (QDistRnd Convergence Style)

  • Add parameters min_hits=[int] (default 5; 0 turns off both the stop and the hit counting: without outC or maxC, RW then records only the codewords lighter than the upper bound, each with a single hit) and cov_cws=[int] (size of the representative set of lowest-weight codewords, default 100).
  • Codeword Multiplicity Tracking:
    • Leverage the existing cw_vec_t->cnt field in p->codewords (which increments every time a duplicate codeword is found), with per-weight histograms of the numbers of codewords and of hits (cw_cnt_w, cw_hits_w).
  • Representative Set: keep up to cov_cws lowest-weight codewords (whole weight classes); heavier codewords are gradually replaced as lighter ones are found, regardless of dW; a new minimum weight is always recorded.
  • Empirical Convergence Condition:
    • In RW (method=1 or method=3), stop when the average number of hits per codeword $\langle n\rangle$ reaches min_hits, both for the minimum-weight codewords and for the representative set (a single codeword suffices, e.g., for a classical code with $k=1$). As in QDistRnd, a lighter codeword is missed with probability $\approx e^{-\langle n\rangle}$, assuming that lighter codewords are found at least as often. Since 0.17.0, the canonical rule of Stage 5 of Task 7 (rw_opt bit 0x10, automatic for quantum codes) replaces this rule.
    • Until the row-slab defaults of 2026-11-18, the hits of all RW steps counted, including the window steps (kwin > 0, and the hybrid windows on every other step for $n \ge 500$, on by default, since 0.17.0 for a DEM, or for matrices with rw_opt=0 or win_hyb > 0) and the row slabs, as well as the CC and finC hits; the window steps find local codewords much more often, so that $e^{-\langle n\rangle}$ can be optimistic for codewords which are not local (found by the uniform steps only). Since then, with a nonzero resolved rw_opt, only the hits of the uniform steps, of CC, and of finC count (and those of the windows of kwin > 0, where no step is uniform), not those of the row slabs and of the hybrid index windows, and $\langle n\rangle$ is the average over the codewords with such a hit (the stop is inactive while no codeword of the minimum weight has one); with a resolved rw_opt of 0, all hits count, as in 0.16.1 (see A rule for the row slabs in Task 7).
  • Hit Uniformity Check: at the end (debug&1, result not certified), a dispersion test of the hit counts in each weight class of the representative set (zero-truncated Poisson; since 2026-11-18, of the hits counted for $\langle n\rangle$); a warning if they are strongly non-uniform.
  • Information-Set Estimate (Python --verbose, and in the binary with the hit uniformity warning): with uniform random information sets, a codeword of weight $w$ is found per RW step with probability $P_1(w) = w\binom{n-w}{s-1}/\binom{n}{s}$, $s = n - \mathrm{rank}\,H$, plus, with the RW pairs (0.14.4, $l$ pivot rows of the buckets), $P_2(w) = \binom{w}{2}\binom{n-w}{s-2}/\binom{n}{s} \cdot \binom{r-w+2}{l}/\binom{r}{l}$ ($r = \mathrm{rank}\,H$); also the RW steps / time for a 1% miss probability (and the extrapolation of $e^{-\langle n\rangle}$ to 1%).
  • Proper estimate for matrices with many small-weight dual vectors: studied in Nov 2026, see Task 6; the implementation is Stage 5 of Task 7.

Task 5: Native SIMD Bit-Matrix Engine (Stage 2)

  • Implement a header-only, self-contained SIMD kernel (src/simd_matrix.h) for $k_{\text{sub}} \le 64$:
    • Flat bit-sliced column layout: uint64_t cols[n].
    • Contiguous row layout: uint64_t rows[64][(n + 63) / 64].
    • Permutation via single-instruction array indexing: cols_perm[j] = cols[perm[j]].
    • Gaussian elimination via AVX2 (_mm256_xor_si256) and AVX-512 (_mm512_xor_si512) vector XOR loops.
    • Zero dynamic heap allocation per trial (malloc/free free inner loop).
    • 100% thread-safe; completely eliminate m4ri_mem_mutex contention in worker threads.

Task 6: Miss-Probability Estimate for Matrices with Many Small-Weight Dual Vectors

  • Find a proper estimate of the probability that RW misses a lighter codeword when the check matrix has many small-weight dual vectors (small-weight trivial vectors in $\ker H$). This is particularly bad for circuit DEMs, whose matrices have a huge number of column triplets summing to zero, as a consequence of the circuit structure: a weight-one error after a CX gate may give a weight-two error, and the net action of the three single-qubit errors is trivial. Both current estimates (Task 4) stay in place until then.
    • Done as a study (Nov 2026, doc/rw_triplet_degeneracies.tex; the triplets are the set $\mathcal{T}_3$ of Task 7): the exact law $\Pr(J)$ of the RW information sets under uniform permutations (Theorem 4, Sec. 6.1: integral, Laplace, and flat-closure formulas, checked against an exact subset DP in Sec. 6.3, which also resolves the "node-marginal paradox"), zero-cost Jensen and Harris–FKG lower bounds on $\ln \Pr(J)$ (Corollary 1, Sec. 6.2), and the Kullback–Leibler form of the concentration (Corollary 2, Sec. 8.5): for no binary matrix with $2 \le \mathrm{rank}\,H \le n - 2$ is the uniform-subset model behind rw_infoset_find_prob (the $P_1$, $P_2$ of Task 4) the RW law, so it can only be a diagnostic. The calibrated alternative counts the hits of the uniform steps per $\mathcal{T}_3$-canonical class (weight-preserving $2 \leftrightarrow 2$ plaquette swaps, Proposition 4, Sec. 7.1) with Good–Turing / Chao1–Chao2 estimates of the unseen classes (Sec. 7.3; the failures of vector-level rules on circuit DEMs in Sec. 7.2). Implementation: Stage 5 of Task 7.
  • Observations (Oct 2026, method=1, min_hits=5, cov_cws=100):
    • The uniform information-set estimate is accurate for some codes (c204: 166 expected vs 173 observed hits of the weight-8 codeword), but extremely pessimistic for DEMs: for gross_uniform_X.dem ($n=8784$, $\mathrm{rank}\,H = 930$), $P_1 \approx 1.5\cdot 10^{-8}$ per step for $w=10$, i.e., $\sim 6\cdot 10^{8}$ steps for 1%, while the hit-based extrapolation needs $\sim 5\cdot 10^{3}$ steps. Steps with localized windows, which find local codewords much more often, are not counted in the uniform model.
    • The hit-based estimate with the representative set is conservative for codes with few minimum-weight codewords (c204: RW stops after $\sim 6000$ steps; the information-set estimate gives 1% after $\sim 90$ steps).
    • Hit counts can be strongly non-uniform within a weight class (surf_d5: some weight-5 logicals are hit 50–70 times, others once), so that $e^{-\langle n\rangle}$ is optimistic there.
  • Possible directions:
    • Separate hit statistics for the uniform and the windowed RW steps (0.14.3): with debug&1, the binary prints the distinct codewords and hits of the three lowest weights found by each kind of step (# RW step types, ...; since 2026-11-18 also the row slabs apart; the codewords in the hash table, i.e., without outC and maxC at most cov_cws of the minimum weight), and the Python model check of the information-set estimate uses the hits of the uniform steps only. Codewords which violate the window model (e.g., time-like codewords with one error per round) are still found only by the uniform steps, which are kept for this. The vector rule of min_hits and the hit uniformity check used the hits of all kinds of steps (cnt) until 2026-11-18; since then, with a nonzero resolved rw_opt, they leave out the hits of the row slabs and of the hybrid index windows (cnt_s, cnt_w; see Task 4 and A rule for the row slabs in Task 7); the canonical rule of Stage 5 of Task 7 (0.17.0) counts only the uniform steps (cnt_u), and its stop is inactive while no uniform step has found a codeword of the minimum weight (the window steps are informational; the status line and the summary say so since 0.17.2).
    • Empirical per-weight hit rates from the representative set, extrapolated to weights below the minimum found.
    • Account for the small-weight trivial vectors explicitly (see Trivial Codeword Statistics below); this may also give a more accurate round estimate (degenerate multiplicity). Studied for the weight-3 ones: the $\mathcal{T}_3$-canonical classes of Sec. 7 of the Nov 2026 notes (Stage 5 of Task 7).
    • To check: the ksub basis refresh (Task 3) puts found low-weight codewords into the basis $N$, which may inflate their hit counts and $\langle n\rangle$.

Task 7: Weight-3 Degeneracies ($\mathcal{T}_3$) in RW: Implementation of the Nov 2026 Study

  • Study (Nov 2026): doc/rw_triplet_degeneracies.tex (with doc/rw_triplet_degeneracies.bib; prototypes and benchmarks in scratch/triplet_rw/, whose raw logs are only in /tmp/exp5/ and /tmp/exp2_out.txt, to be copied to scratch/triplet_rw/logs/; summary in scratch/reports/triplet_rw_analysis.md). Weight-3 degeneracies (column triplets with zero sum in $H$ and $L$) come from the CNOT hook triangles of the circuit (Prop. 1, Sec. 3.1), are found exactly with $\sum_i \binom{|G_i|}{2}$ hash probes (Lemma 1, Sec. 3.2), and span the whole degeneracy space $\ker H \cap \ker L$ on 12 of 14 circuit DEMs (Sec. 3.3). Their effects on RW (ambushed pivot pairs, contraction, Stern buckets; Secs. 4–5), the exact information-set law and the miss estimate (Secs. 6 and 8.5; Task 6), the canonical stopping rule (Sec. 7), and the answers for the three non-multi-round regimes (Sec. 8) lead to the roadmap of Sec. 9 (Stages 1–5 and dispatch rules D1–D5; stage matrix in Sec. 8.6):
    • Q1 — Extended CSS matrices and code-sized models (Sec. 8.2, Prop. 5, Table 9): CNOT-order prefix hooks split every check of weight $w_g \ge 3$ into $w_g - 2$ triangles summing to $1_g$ ($\dim \mathcal{D}_{\rm ext} = \dim \mathcal{D} + n_{\rm h}$, generically $n_{\rm h} = \sum_g (w_g - 3)$ and $|\mathcal{T}_3^{\rm ext}| \ge \sum_g (w_g - 2)$), proving $\mathrm{GAP}_{\rm ext} = 0$ even when $\mathcal{T}_3 = \emptyset$ on the bare code; the measured-basis model of compute_model_lower_bound() equals the hook-extended CSS matrix up to column order ($m \times 5m$ on all six BB circuits). Stages 1, 2, and 5 work in full ($2.6\times$–$5.9\times$ hits/step for V4_cnt_uni, up to $12.5\times$ for V6_cnt_win on DEM-ordered models) once Stage 1 runs on matrix inputs too; Stages 3 and 4 (no time axis, $\le 12.7$ KiB in L1/L2) and win=256 on data-then-hooks matrices stay off.
    • Q2 — Static degenerate CSS and 2BGA codes $(H_X, H_Z)$ (Sec. 8.3, Thm. 5, Prop. 6, Table 10): when $w_{\rm deg} = 3$ (e.g., SHYPS gauge sector, $|\mathcal{T}_3| = 525$, $\mathrm{GAP} = 0$), Stages 1, 2, and 5 apply verbatim ($266\times$–$366\times$ hits/s). On the 7 Bicycle Race 2bga_* codes ($w = 5$–$9$), meet-in-the-middle ($w \le 6$) plus ISD finds $w_{\rm deg} = w_{\max}$ ($\mathcal{T}_3 = \emptyset$); in general 2BGA codes (Lin–Pryadko 2024), subgroup/coset combinations can give extra light generators $w < w_{\max}$ (weight-3 ones caught by Lemma 1, $w \ge 4$ via low-weight search of $\mathrm{rowspan}(G)$ or extra finG rows). With explicit generators $\mathcal{G}$ (finG), steepest-descent $\mathcal{G}$-shortening up to $d_{\max} + w_{\mathcal{G}} - 2$ lowers $5.7%$–$88%$ of $p = 1$ candidates in the 24 sectors (supplying $92%$–$100%$ of the weight-$d$ hits on 2bga_288_4 and 2bga_292 in the $X$ sectors of Table 10, and 4 of 5 in the $Z$ sector of 2bga_292), and omitting realized generators $C_P(x) \in \mathcal{G}$ from Stern Bucket 0 is loss-free ($0$ lost in $24$ sectors; unlisted $w_x \ge 3$ trivial columns must not be filtered). Even-weight generators give $(w/2) \leftrightarrow (w/2)$ sibling swaps ($\mathrm{canon}_{\mathcal{E}}$); odd-weight generators alone give none.
    • Q3 — Single-round ($T = 1$) circuit DEMs, reduced vs. unreduced (Sec. 8.4, Lemma 2, Table 11): in a CSS memory circuit with $T = 1$ cycle (rounds=0 when cycle 1 precedes REPEAT), minority checks are measured once, so zero minority detectors exist (drop=auto deletes $0$ detectors, full merged DEM $=$ CSS-reduced DEM, and each DEPOLARIZE2 yields $\le 3$ distinct nonzero columns; $n/m \le 9.4$, whereas two-sector reduction begins at $T = 2$, and non-CSS color_xyz stays irreducible). Within-cycle CNOT triangles keep $\mathrm{GAP} = 0$, so Stages 1, 2, and 5 stay on ($3.7\times$–$45\times$ hits/s for V4_cnt_uni, up to $1075\times$ for V6_cnt_win), Stages 3 and 4 stay off, and win=256 still yields $6.5\times$–$33\times$ hits/step ($6.0\times$–$31\times$ hits/s) at $T = 1$ for $n \gtrsim 10^3$ on mitten and SHYPS from Stim's spatial column order (vanishing under random column permutation; on dgross_288, $n = 1728$, only the window variants found weight-18 hits: 47 and 115 against 0).
    • **Cross-regime $\Pr(J)$ concentration and termination** (Secs. 8.5–8.6, Cor. 2, Tables 12–13): $\kappa(H) = \mathbb{E}_{\Pr}[\ln \Pr(J)] + \ln\binom{n}{r} = D_{\rm KL}(\Pr | U_r) > 0$ for every binary matrix with $2 \le \mathrm{rank}\,H \le n - 2$ (exclusion of dependent $r$-subsets plus basis non-uniformity), so rw_infoset_find_prob is never exact and must stay a diagnostic. Canonical cnt_u Good–Turing / Chao1–Chao2 stopping halts $5\times$–$13\times$ earlier with $0$ missed logical classes when $M_{\rm eff} \gg 1$ (16–111), $1.9\times$–$2.2\times$ earlier on the bb_72 extended matrix and model with $M_{\rm eff} = 3.5$ (1.3–2.0% of the swap clusters missed), and matches vector-level behavior when $M_{\rm eff} = 1$ (the prototype counted the Chao1 abundances of the hits, not the Chao2 step incidences of the implementation).
