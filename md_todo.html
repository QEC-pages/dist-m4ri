1. High-Priority Roadmap: High-Performance RW Overhaul

This work optimizes the Random Information-Set Decoding (RW, method=1) algorithm to achieve linear multicore scaling (32–128 cores), minimal per-core memory footprint, and enhanced hit rates for quantum CSS codes and Detector Error Models (DEMs).

Inspired by sqetch (arXiv:2607.28795, Appendix H) and the empirical convergence criteria in QDistRnd (http://github.com/QEC-pages/QDistRnd).

Implementation Strategy

  • Stage 1 (Immediate / Functional Baseline):
    • Implement Tasks 1–4 using libm4ri matrix primitives (mzd_kernel_left_pluq, mzd_copy_row, mzd_echelonize).
    • Validate mathematical correctness, hit-rate scaling, and backward compatibility (ksub=0 retains original RW).
  • Stage 2 (Hardware-Optimized SIMD Engine):
    • For worker thread hot loops ($k_{\text{sub}} \le 64$), replace libm4ri with a zero-allocation, thread-safe, header-only AVX2 / AVX-512 bit-matrix kernel.
    • Utilize bit-sliced column representations (uint64_t cols[n]) to eliminate column transposition passes and completely remove the global m4ri_mem_mutex.

Task 1: Subspace Sketching (<tt>ksub</tt>, experimental) for In-Cache Multicore Scaling

  • [x] Add CLI parameter ksub=[int] (default 0 retains original full-matrix RW).
  • [x] Main Thread Precomputation:
    • Compute a basis of the null space $N = \ker(H)$ (dimension $\nu \times n$, where $\nu = n - \mathrm{rank}(H)$) once using mzd_kernel_left_pluq.
    • Store $N$ as a global read-only matrix shared across worker threads.
  • [x] Worker Thread In-Cache Working Set:
    • For $k_{\text{sub}} > 0$, allocate a compact $k_{\text{sub}} \times n$ matrix instead of the full $m \times n$ check matrix.
    • For $k_{\text{sub}} = 64$ and $n = 5000$, working memory per thread is $\approx 40\text{–}80 \text{ KB}$, fitting entirely within private L1/L2 cache and eliminating L3 cache and DRAM bandwidth contention.
  • [x] Per-Trial Hot Loop:
    1. Sample $k_{\text{sub}}$ distinct rows of $N$ (partial Fisher–Yates shuffle of the row indices; rows drawn with replacement would repeat and reduce the rank) into the thread-local working matrix M_sub.
    2. Perform in-place RREF via gauss_one(M_sub, perm->values[i], rank) in permuted column order (stopping as soon as rank == ksub, avoiding matrix transpositions and non-thread-safe m4ri_mmc allocations).
    3. Directly extract candidate codewords from the reduced non-zero rows (already in sorted original column coordinates; no dual transposition, coordinate unpermutation, or qsort needed).
    4. Test logical non-triviality against $L$ (column masks of $L$, see Faster Logical Check), and atomically update dmax.
  • Findings (Oct 2026, ksub forced also for $m < \nu$, 8 threads): ksub explores only the span of $k_{\text{sub}}$ rows of the fixed basis $N$ in each step, so a codeword is found only if all basis rows in its expansion are sampled. The hit counts are then concentrated on a few codewords, and min_hits stops RW early: e.g., for bb72_si1000_X.dem, after $\sim 2500$ steps with only 4–7 distinct codewords of weight 6 (full RW: 100 distinct codewords after $\sim 40000$ steps); for torus60_d14_X.dem, a codeword of weight 6 took 3–14 s instead of 3–15 ms. For c1920H.mmx (where ksub is allowed), the lightest codewords found in 20 s were similar to full RW. The fallback rule $m < \nu \Rightarrow$ ksub=0 thus stays (it disables ksub for DEMs and most quantum codes).
  • [x] ksub is kept for now, but marked experimental (should not be used) in the documentation, --help, and --morehelp; a warning is printed whenever ksub>0 is given for RW (with or without min_hits, regardless of debug; in Python, once per compute_*_distance() call), as a reminder that the option does not do what it is supposed to.
  • [ ] Find a subspace sampling for which the hit counts are uniform (or drop ksub).

Task 2: Localized & Windowed Column Permutations for DEMs

  • [x] Add parameters kwin=[int] (window size $W$, default 0 = uniform random permutation; alias win=[int]) and win_mode=[0|1] (default 0).
  • [x] Window Construction:
    • Pick a seed column $j_0 \in [0, n-1]$ uniformly at random per trial.
    • Mode 0 (Tanner Graph BFS Neighbors): Perform BFS on the bipartite graph between columns and check rows starting from $j_0$ to gather $W$ geometrically/physically connected error mechanisms. Use a monotonic visit marker to avoid clearing arrays across trials.
    • Mode 1 (Spacetime / Index Proximity): Define a contiguous coordinate window $[j_0, j_0 + W) \pmod n$ around $j_0$.
  • [x] Permutation Layout:
    • Place the internally shuffled $W$ window columns in the first $W$ positions ($0 \dots W-1$).
    • Place the remaining $n - W$ columns at the tail ($W \dots n-1$).
  • [x] Support Overlap Filter & Windowed Echelonization:
    • Optionally restrict row sampling to basis vectors of $N$ whose support intersects window $W$.
    • Exploit left-to-right echelonization: Gaussian elimination pivots first on the window columns, producing localized candidate codewords with support concentrated around the seed column $j_0$.

Task 3: Adaptive Basis Evolution & Periodic Refresh of $N$

  • [x] Density Degradation Prevention:
    • Avoid unconstrained random row mixing ($N_i \leftarrow N_i \oplus N_j$), which quickly drives basis row weights to $\approx n/2$ and degrades ISD hit rates.
  • [x] Steinitz Exchange with Discovered Codewords:
    • Maintain an atomic pool of the lowest-weight non-trivial logical codewords found by worker threads.
    • Periodically substitute these lighter codewords into the basis $N$ using Gaussian elimination to maintain linear independence while systematically reducing the average row weight of the basis.
  • [x] **Periodic Re-Echelonization (refresh=[int])**:
    • Every refresh trials, generate a fresh canonical basis of $\ker(H)$ by re-echelonizing under a new global column permutation $\Pi$ (protected by a per-batch pthread_rwlock_t). This breaks sampling blind spots without accumulating row density.
  • [ ] Lock-Free Double Buffering (RCU Pattern):
    • Maintain _Atomic(mzd_t *) N_active and background buffer N_staging.
    • Worker threads acquire a local snapshot of N_active per batch without locking.
    • The coordinator prepares N_staging and atomically swaps N_active with release semantics.

Task 4: Hit-Count Stopping Criterion (<tt>QDistRnd</tt> Convergence Style)

  • [x] Add parameters min_hits=[int] (default 5, 0 = disabled) and cov_cws=[int] (size of the representative set of lowest-weight codewords, default 100).
  • [x] Codeword Multiplicity Tracking:
    • Leverage the existing cw_vec_t->cnt field in p->codewords (which increments every time a duplicate codeword is found), with per-weight histograms of the numbers of codewords and of hits (cw_cnt_w, cw_hits_w).
  • [x] Representative Set: keep up to cov_cws lowest-weight codewords (whole weight classes); heavier codewords are gradually replaced as lighter ones are found, regardless of dW; a new minimum weight is always recorded.
  • [x] Empirical Convergence Condition:
    • In RW (method=1 or method=3), stop when the average number of hits per codeword $\langle n\rangle$ reaches min_hits, both for the minimum-weight codewords and for the representative set (a single codeword suffices, e.g., for a classical code with $k=1$). As in QDistRnd, a lighter codeword is missed with probability $\approx e^{-\langle n\rangle}$, assuming that lighter codewords are found at least as often.
  • [x] Hit Uniformity Check: at the end (debug&1, result not certified), a dispersion test of the hit counts in each weight class of the representative set (zero-truncated Poisson); a warning if they are strongly non-uniform.
  • [x] Information-Set Estimate (Python --verbose, and in the binary with the hit uniformity warning): with uniform random information sets, a codeword of weight $w$ is found per RW step with probability $P_1(w) = w\binom{n-w}{s-1}/\binom{n}{s}$, $s = n - \mathrm{rank}\,H$; also the RW steps / time for a 1% miss probability (and the extrapolation of $e^{-\langle n\rangle}$ to 1%).
  • [ ] Proper estimate for matrices with many small-weight dual vectors: see Task 6.

Task 5: Native SIMD Bit-Matrix Engine (Stage 2)

  • [ ] Implement a header-only, self-contained SIMD kernel (src/simd_matrix.h) for $k_{\text{sub}} \le 64$:
    • Flat bit-sliced column layout: uint64_t cols[n].
    • Contiguous row layout: uint64_t rows[64][(n + 63) / 64].
    • Permutation via single-instruction array indexing: cols_perm[j] = cols[perm[j]].
    • Gaussian elimination via AVX2 (_mm256_xor_si256) and AVX-512 (_mm512_xor_si512) vector XOR loops.
    • Zero dynamic heap allocation per trial (malloc/free free inner loop).
    • 100% thread-safe; completely eliminate m4ri_mem_mutex contention in worker threads.

Task 6: Miss-Probability Estimate for Matrices with Many Small-Weight Dual Vectors

  • [ ] Find a proper estimate of the probability that RW misses a lighter codeword when the check matrix has many small-weight dual vectors (small-weight trivial vectors in $\ker H$). This is particularly bad for circuit DEMs, whose matrices have a huge number of column triplets summing to zero, as a consequence of the circuit structure: a weight-one error after a CX gate may give a weight-two error, and the net action of the three single-qubit errors is trivial. Both current estimates (Task 4) stay in place until then.
  • Observations (Oct 2026, method=1, min_hits=5, cov_cws=100):
    • The uniform information-set estimate is accurate for some codes (c204: 166 expected vs 173 observed hits of the weight-8 codeword), but extremely pessimistic for DEMs: for gross_uniform_X.dem ($n=8784$, $\mathrm{rank}\,H = 930$), $P_1 \approx 1.5\cdot 10^{-8}$ per step for $w=10$, i.e., $\sim 6\cdot 10^{8}$ steps for 1%, while the hit-based extrapolation needs $\sim 5\cdot 10^{3}$ steps. Steps with localized windows, which find local codewords much more often, are not counted in the uniform model.
    • The hit-based estimate with the representative set is conservative for codes with few minimum-weight codewords (c204: RW stops after $\sim 6000$ steps; the information-set estimate gives 1% after $\sim 90$ steps).
    • Hit counts can be strongly non-uniform within a weight class (surf_d5: some weight-5 logicals are hit 50–70 times, others once), so that $e^{-\langle n\rangle}$ is optimistic there.
  • Possible directions:
    • [x] Separate hit statistics for the uniform and the windowed RW steps (0.14.3): with debug&1, the binary prints the distinct codewords and hits of the three lowest weights found by each kind of step (# RW step types, ...), and the Python model check of the information-set estimate uses the hits of the uniform steps only. Codewords which violate the window model (e.g., time-like codewords with one error per round) are still found only by the uniform steps, which are kept for this.
    • Empirical per-weight hit rates from the representative set, extrapolated to weights below the minimum found.
    • Account for the small-weight trivial vectors explicitly (see Trivial Codeword Statistics below); this may also give a more accurate round estimate (degenerate multiplicity).
    • To check: the ksub basis refresh (Task 3) puts found low-weight codewords into the basis $N$, which may inflate their hit counts and $\langle n\rangle$.

2. Additional Algorithmic Explorations & Enhancements

  • [x] RW with pairs of non-pivot columns (Lee–Brickell / Stern, $p=2$) (0.14.4, option pairs, on by default; scratch/speedup/RESULTS.md, experiment (h)): a codeword with exactly two non-pivot columns is the sum of their two circuits. With uniform information sets, a given codeword of weight $w$ is found $P_2/P_1 = (w-1)(n-r-1)/(2(r-w+2))$ times more often per step ($r = \mathrm{rank}\,H$, all pairs): about 10 for the dgross CSS code ($w = 18$), 20–100 for the reduced DEMs.
    • Prototype (numba, scratch/speedup/p2_proto.py, p2_stern.py): 10–35x more minimum-weight hits per step on bb_72, bb_90, and gross; all pairs take about 3x the time of the elimination, and the circuits are sparse, so that the buckets of a Stern collision search ($l$ random pivot rows) are very uneven.
    • In C: the non-pivot columns are sorted (radix sort) by a hash of their bits in $l$ random pivot rows, then by "zero L syndrome" and by weight. In a bucket, only the pairs whose weights differ by less than the weight limit are checked (word-wise popcount with early exit); the pairs of two columns with zero L syndromes (light trivial codewords, most columns of a circuit DEM) or with equal L syndromes are skipped (the rows of L reduced with the pivot rows, for at most 64 rows of L). The codewords of the pairs are recorded up to the weight of the upper bound (plus dW when collecting). Auto: $l = \lceil\log_2(n-r)\rceil$, reduced while a codeword of the weight of the upper bound is kept with the probability $\binom{r-l}{w-2}/\binom{r}{w-2} < 0.8$. The information-set estimate includes the $P_2$ term, and debug&1 prints the pairs checked per step and the codewords from pairs and single columns.
    • Results (fixed RW steps): the minimum-weight codewords of circuit DEMs 7–26x more often per second (bb_72 7x, gross 22x, surf_d7 and mitten_150 26x); dgross: weight 18 in 3000 steps on 32 threads (20 without pairs; 2% more time per step); bb_360: 24 in 600 steps (26); classical LDPC codes with large distances: c1920H 210 instead of 320 in 1000 steps (auto $l = 1$). Small codes: 2–5x longer steps (more hits recorded under the codeword mutex), but min_hits is reached in 2–34x fewer steps, in about the same time or less.
    • Possible follow-ups: thread-local batches of the recorded hits (the codeword mutex limits small codes with many threads, also without pairs); a cost model for $l$ (time of the pairs vs the elimination) instead of the fixed keep probability 0.8; triples ($p=3$) for small ranks.
    • [x] 0.14.6: a work bound for the auto $l$ (benchmark/BENCHMARK.md, Section 8; scratch/bench_0.14.5/): $l$ is at least the $l$ at which the about $(n-r)^2/2^{l+1}$ pairs of a step are within about the work of its elimination, $rn/16$ pairs (or $2^{20}$ pairs for small matrices), and the stop flags and the upper bound are also polled within the buckets (every 65536 pairs). Early in a run, while the upper bound is far above the distance, the keep probability alone gave $l = 1$ (all pairs in two buckets): 0.14.5 on bb_756 completed no RW step in the first 32 s and did not stop at its timeout, and on mitten_270 took 0.6 s of RW to the distance instead of 0.16 s (0.14.3). The bound gives $l \ge 6$ for these DEMs (0.14.6: 0.12 s of RW to the distance of mitten_270, and bb_756 stops at its timeout), and no change for codes with $n - r < r$ (c1920H).
  • [x] RW thread throttle for huge matrices (0.14.3; scratch/speedup/RESULTS.md, experiments (a) and (e)): above 15 MB of dense RW memory per thread, at most 32 RW threads, within a quarter of the physical memory (at least 2; 1.5 GB if the physical memory is not known), instead of about 1.5 GB in total. The memory bus saturates at 32-64 RW threads whatever the matrix size.
    • bb_756 (reduced, 0.43 GB per thread): 32 RW threads and 1.49 steps/s by default, against 3 threads and 0.23 steps/s before (6.5x).
    • bb_360 (49 MB per thread): 32 RW threads as before (45 steps/s).
  • [x] RW windows for big DEMs (0.14.3; scratch/speedup/RESULTS.md, experiments (b), (e), (f)): the hybrid windows (every other RW step) have 256 columns for a DEM, 512 for matrices (win_hyb).
    • Windows of one and two rounds of columns (round estimate from the DEM) were slower than 512: a window of W consecutive DEM columns touches only so many detectors, e.g., one round ($L \approx 10D$ columns) about $2D$, so that most of its columns cannot be pivots.
    • A scan of single window sizes on six reduced DEMs (gross, dgross, bb_360, three mitten circuits): the best size is 192-256 columns for all of them (1.3-3.6 D), 2-10x better than 512; on dgross, about 10 distinct weight-18 codewords per $2 \cdot 10^4$ steps with 256 columns, 0-2 with 512 or with one round. Cycling several sizes is worse than the best single size (the optimum is sharp). Matrices of codes gain nothing from 256.
    • The round estimate (D detectors and L columns per round) is printed with debug&1 only.
    • Next:
      • the window size for much larger codes (bb_756: not measured; the optimum did not grow with D from 60 to 180);
      • an adaptive window size (e.g., from the light codewords found by each size), or a model of the optimum from the span of the minimum-weight codewords in the column order;
      • fewer uniform steps for big DEMs (keeping some for the statistics and for codewords which are not local);
      • window-restricted elimination (section 4).
  • [ ] Upper bounds from code logicals: in a memory circuit, a minimum-weight logical of the code applied as single-qubit data errors at one time step flips no detector, so it is a DEM codeword of weight $d_{\rm code}$ (with si1000-type noise these errors are error mechanisms).
    • Python could map the data errors to DEM columns by their detector signatures and pass the codeword as finC.
    • This gives at once dgross $\le 18$, bb_360 $\le 24$, bb_756 $\le 34$ (RW: 18, 23, 58).
    • [ ] Code distance of a circuit as a fast upper bound (for DEMs and Stim circuits, especially large ones): extract the code from the circuit with the functions of tmp/distance.py (extract_matrices_and_hooks(): Hx, Hz, Lx, Lz from the ancilla interactions and the observables; compute_css_distance() for the code), and compute the distance of the sector of the memory basis (Z-type logicals for an X-basis memory: H = Hx, L = Lx). It is code-sized (seconds where the DEM takes hours) and an upper bound on the circuit distance whenever the logical can be applied by single faults (data errors, or flips of the final data measurements, as with the uniform noise).
      • Certify it: lift the logical to a DEM codeword (the error mechanisms of the flips of the final data measurements on its support, found by their detector signatures), check $Hx = 0$, $Lx \ne 0$, and pass it to the DEM run as finC (an upper bound dmax for CC and RW); report a note if no lift exists.
      • A DEM-only variant without the qubit classification of distance.py (which fails, e.g., for the hef circuits, with no X-check ancillas found, and for routing circuits): the error mechanisms which touch only the final detectors (the flips of the final data measurements) form a sub-DEM which is the code itself (rows: the checks of the measured basis, as in the code-sized model); its distance is an upper bound, and its codewords are DEM codewords.
      • Python: a function (e.g., compute_code_upper_bound(circuit)) and a CLI option, the bound stored as dmax in the cache record of the DEM (with its codewords); together with compute_model_lower_bound(), the bracket $[d_{\rm model}, d_{\rm code}]$ for the circuit without CC or RW on the DEM.
  • [ ] Incremental information sets (Canteaut–Chabaud), for huge DEMs: swap one column in or out of the information set per step (a single pivot change, about $r n/64$ word operations) instead of a full elimination.
    • This gives many more information sets per second (bb_756: 12–50 s per full elimination).
    • Consecutive sets are correlated: a separate upper-bound mode without min_hits and the miss estimate.
  • [ ] Trivial Codeword Statistics:
    • Maintain counters of trivial codewords (stabilizers in quantum codes) of weights below $w_{\max}$ to monitor code degeneracy profile and ISD efficiency.
  • [x] Sorting Optimization:
    • The codeword supports ee are sorted with the type-specific rci_quick_sort from sort.h (bitonic sort for up to 16 elements) instead of the generic qsort; with ksub > 0, the supports are extracted already sorted.
  • [ ] Sparse Gaussian Elimination:
    • Evaluate whether sparse elimination (e.g. CSR row combining) can outperform dense bit-matrices for very large, highly sparse DEMs where $k_{\text{sub}}$ is small.
  • [x] Faster Logical Check:
    • sparse_syndrome_non_zero(L, ...) cost $O(\mathrm{nnz}(L))$ per candidate, and it was the largest part of a RW step for DEMs, where most candidates below the weight limit are trivial (e.g., 248 candidates per step for bb72_si1000_X.dem, 1.5 ms of a 1.9 ms step), and also of CC rounds on DEMs (trivial zero-syndrome clusters).
    • Now the column bit masks of $L$ (colmask_t, p->maskL, $\lceil k/64\rceil$ words per column) give the check in $O(w)$ operations, for RW (also before sorting the support), ksub RW, and CC. Same results, one thread, the same RW steps (times include reading the input): bb72_si1000_X.dem RW 3.6 s $\to$ 0.63 s, CC (wmax=6) 2.4 s $\to$ 1.1 s, method=3 3.2 s $\to$ 1.2 s; gross_uniform_X.dem 3.3 s $\to$ 1.5 s; QX900 0.68 s $\to$ 0.23 s; surf_d5 0.77 s $\to$ 0.51 s.
  • [x] CC row order (sort_rows, 0.14.1): CC extends a cluster by the columns of the first unsatisfied row (in row order), so the binary sorts the rows of $H$ by increasing weight (stable) for matrices (sort_rows=1, the default; sort_rows=0 for a DEM, whose detectors are in time order).
    • Extended CSS matrices with hook columns (tmp/distance.py; rows of weight 5–103): 1.2–2.3x to certify the distance, 1.7–4.2x to enumerate all codewords of a weight.
    • DEMs, and matrices exported from DEMs: 1.3–4x slower when sorted, since the first detector in time order has most of its columns before the start column of the cluster.
    • RW is unchanged (the same codewords with the same seed).
    • Choosing the row with the fewest admissible columns dynamically gave 2–23% fewer CC loop iterations on DEMs in a model, about as much as its per-node cost (scratch/rowsort/).
  • [x] RW Step Profile (Oct 2026, one thread, after the faster logical check): the Gaussian elimination takes 70–95% of a RW step for DEMs (bb72_si1000_X.dem: 215 of $\sim$310 µs; gross_uniform_X.dem: 6.8 of 7.8 ms), the transposition 7–15%, the extraction of the candidates the rest. Faster elimination (Task 5, or M4RI on a column-permuted copy, which needs thread-safe allocations) is the next step.
    • The weight of each candidate is now counted first (word-wise popcount, ending at the weight limit), and only the candidates below the limit are formed: surf_d5 $-11%$, c1920H.mmx $-9%$ of the RW time.
    • With redundant rows of $H$, the RW matrices keep only the $\mathrm{rank}\,H$ non-zero rows after the first step, so that the transposition skips the zero rows.
    • Contention on cw_mutex is negligible: only the candidates below the weight limit and with $Lc \neq 0$ are recorded, and with min_hits about min_hits $\times$ cov_cws hits are recorded until convergence (e.g., 1.4 µs of lock wait per step of $\sim$260 µs for surf_d5 with 32 threads); it only shows in runs of a few milliseconds.
  • [x] Distance Benchmark Update: the overnight run of 0.14.0 (Oct 2026, benchmark/BENCHMARK.md) certified the distances of all benchmark circuits up to gross. Still open: double gross, bb_360, and bb_756; see Bounds for the largest circuits in section 4.

    • RW and information sets: Prange (1962); Lee–Brickell (1988) and Stern (1989) for the pairs ($p = 2$) and the collision buckets; Canteaut–Chabaud (incremental information sets); later information-set decoding (Dumer; May–Meurer–Thomae; Becker–Joux–May–Meurer) for further gains; QDistRnd (random information sets for quantum codes, the hit-count convergence criterion); prior use of localized windows or time slabs for circuit-level distances.
    • Elimination: the Method of the Four Russians (Arlazarov, Dinic, Kronrod, Faradzev) and M4RI (Albrecht, Bard; Gray-code tables), for the scattered column orders of RW.
    • CC: connected-cluster enumeration (Dumer, Kovalev, Pryadko 2017), the meet-in-the-middle hash for the last two levels, work units and thread scheduling.
    • Statistics: index-of-dispersion tests and zero-truncated Poisson fits of the hit counts.
    • Circuit-level distance: stim's search for undetectable logical errors, SAT/MaxSAT and ILP approaches (e.g., for the BB codes), spacetime codes (Delfosse, Paetznick), hook errors and distance-preserving schedules, extended CSS distances with hooks, exact reductions of DEMs (dropped detectors), and code-sized or folded models as certified lower bounds.
    • Memory-bandwidth-aware thread throttling for dense GF(2) linear algebra.

3. Operational Modes Reference

Mode: Distance Verification

  • Given a suspected distance $d$ (e.g., $d = 10$), run method=1 dmax=10 wmin=9 min_hits=0.
  • RW ignores codewords of weight $\ge 10$ and ends as soon as it finds a non-trivial codeword of weight $w \le 9$ (output 1 w S; with debug&1, the stop line found a codeword of weight w <= wmin=9).
  • If no lighter codeword is found in the steps RW steps, the output is 1 10 S (the supplied upper bound). (The legacy dist_m4ri_old method=1 wmax=10 wmin=9 outputs -w or 0.)

Mode: Upper Bound Search with Hit-Count Saturation

  • Run RW with method=1 steps=N min_hits=M cov_cws=K.
  • Collects the lowest-weight codewords into the hash table, terminating when the average number of hits per codeword reaches $M$, both for the minimum-weight codewords and for the representative set of $K$ lowest-weight codewords.

More improvements

  • [x] try verifying (using cluster decomposition from vecdec (?)) if the constructed / imported non-trivial CW can be decomposed into disconnected components. Keep only non-trivial part (does it ever happen? how expensive is this?)
    • Answer (Oct 2026): it never happens for RW. A RW candidate is the fundamental circuit of a non-pivot column (the unique kernel vector on the pivots plus that column), i.e., a minimal codeword, and a disconnected codeword is never minimal (each component is itself in $\ker H$).   • [ ] Row reductions of a DEM, with lifting and verification in C (generalizes the two items above): replacing $H$ by $RH$ with rows in the row space of $H$ (deleting or summing detector rows), with the observables $L$ unchanged, can only lower the distance, $d_R \le d_{\rm full}$; deleting or merging observables could raise it. Columns equal on $(RH, L)$ merge into classes, and $d_R = d_{\rm full}$ iff some minimum-weight reduced codeword lifts (one full column per class, with $Hx = 0$).
    • Exact reductions ("clean twins"): a detector set $M$ can be deleted together with all columns touching it if each such column has a twin with the same pattern on the other detectors and on $L$ that does not touch $M$ (columns with no other detector and no observable are dropped). The reduced DEM is a submatrix of the full one with the same distance, and its codewords are full codewords (no lifting). The simplified DEM is the CSS case ($M$ = the minority detectors). The condition must hold for $M$ as a whole (single minority detectors usually fail it), so candidate sets (sectors, coordinate classes) are tested as groups.
    • Lossy reductions: summing the detectors of each check over all rounds gives the code-sized model of the net data effects (see above), a cheap certified lower bound, tight or not depending on the schedule. Sums over blocks of at least 2 rounds give exactly the same bound: a model codeword realized within one block (its partial syndromes at rounds $t$ and $t+1$ in the same row) is invisible again; see the folded models below. Lifting: one member per class with the deleted or summed rows cancelling (meet-in-the-middle over the members, within a time window), else a repair with extra columns (a heavier upper bound); refinement: split the summed rows of the checks where a lift failed back into per-round detectors and solve again (row generation), until a lift matches the lower bound. Merge the equal columns first: summed rows otherwise get huge row weights for CC.
    • In C: the full DEM and a reduction spec (a delete list or an aggregation map from Python, or rules on detector coordinates); build $RH$, merge equal columns (map from each class to its full columns), run RW or CC on the reduced matrix, lift and verify each candidate ($Hx = 0$, $Lx \ne 0$ for the full DEM), and write the full codewords to outC. Report $d_R$ (certified once CC is done) as dmin and the verified lifts as dmax for the full DEM; min_hits then refers to $d_R$, so exactness only when the bounds meet.
    • Order: clean-twin deletion together with equal-column merging (replaces the Python simplified/full detector map, verified automatically); then the code-sized model as a lower bound for large distances; adaptive lifting and refinement as research.
  • [ ] Folded models (research): a refinement of the code-sized model which keeps the timing within the rounds.
    • Rows $R_{h,c} = \sum_{t \equiv c \pmod p} D_h^t$ for each check $h$ and residue $c$, with $p \ge 2$ (the boundary detectors in their residue classes): sums of detector rows, so that the bound is valid (any row reduction is).
    • Consecutive rounds are in different rows: the partial syndrome $P$ which the faults of one round leave (detectors $P$ at rounds $t$ and $t+1$, which cancel in the code-sized model) is seen as in the DEM, which is why the lightest codewords of the code-sized model do not lift.
    • Bounds: $d_{\rm model} \le d_{\rm fold}(p) \le d$, and $d_{\rm fold}(p) \le d_{\rm fold}(p')$ if $p$ divides $p'$ (each mod-$p$ row is a sum of mod-$p'$ rows).
    • Size: like a DEM with $p$ rounds and periodic time, e.g., about $300 \times 3000$ for double gross with $p = 2$ (reduced DEM: $2736 \times 26208$). Spurious codewords remain (equal partial syndromes $p$ rounds apart cancel), and the row weights are those of the DEM, so that CC costs more than on the code-sized model.
